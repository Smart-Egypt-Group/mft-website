Why you can trust the result

Changes to your report record leave a trace.

Five guarantees built into SEG and actually tested, not promises on a policy page.

Every report and approval action is hash-chained
Every report and approval action is written to a log where each entry is mathematically chained to the one before. An edited or deleted row breaks the chain when the log is verified, and the break is located. We tested this in production with a direct database edit.
Your data is completely isolated from every other client
Each organisation lives in its own space, and anyone reaching for another client’s data finds that it does not exist for them. Isolation was verified on all seven organisations when the data was backfilled, is probed live in production with two organisations, and is covered by automated tests.
Your backup has actually been restored, not just taken
A backup only counts once it has been restored. We restored a full snapshot of all four production databases (31 July 2026) and verified it; a full rebuild on a new server is the next drill.
The platform runs with the least privilege possible
Platform services run under non-administrative accounts with no extra system privileges, verified on the running servers rather than on paper.
More than 9,900 automated tests before every update
Test code is 87% the size of the platform itself, and some of those tests guard the governance rules: one of them stopped a rule-breaking change before it reached any client.

Test and check counts are read from the platform code (2026-11-05); the other guarantees were measured in a documented internal review of SEG (August 2026). Details on the trust page.
